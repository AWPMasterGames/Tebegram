# Tebegram

**Мессенджер для локальной сети: десктопное приложение, сервер и веб-версия — на одном протоколе.**

Обмен сообщениями и файлами, групповые чаты и голосовая связь. Разворачивается копированием папки: без базы данных, контейнеров и внешних сервисов. Работает в изолированной сети без доступа в интернет.

## ✨ Возможности

| | |
|---|---|
| **Переписка** | личные и групповые чаты, папки, поиск по контактам и по всем пользователям сервера |
| **Статусы сообщений** | часики → галочка (сервер принял) → две галочки (собеседник открыл чат), красный «!» при ошибке |
| **Файлы** | любой тип до 16 МБ, превью фото и видео прямо в чате, индикатор загрузки |
| **Кэш медиа** | скачанное хранится локально и не качается повторно; лимит и очистка в настройках |
| **Голосовая связь** | звонки между двумя компьютерами или между двумя браузерами, шумоподавление |
| **Оформление** | светлая и тёмная темы, переключение без перезапуска |
| **Веб-версия** | PWA: ставится на телефон, работает офлайн, обновляется сама |
| **Установка** | установщик Windows с автоматической проверкой обновлений |

## 🚀 Быстрый старт

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0). Клиент собирается только под Windows, сервер — под любой системой.

**1. Сервер**

```bash
cd Tebegram-server
dotnet run
```

Слушает порт `5000`. Проверить: открыть `http://localhost:5000/Test` — должно ответить `HI!`.

**2. Десктопный клиент**

```bash
dotnet run --project Tebegram-client
```

Либо скачать готовый установщик со [страницы релизов](https://github.com/AWPMasterGames/Tebegram/releases/latest).

**3. Веб-версия**

Уже запущенный сервер раздаёт её сам — откройте `http://localhost:5000/app`.

**Как клиент находит сервер.** При входе в левом верхнем углу выбирается источник адреса: **main** — адрес берётся из [`Adress.txt`](Adress.txt) в этом репозитории, **Другой** — вводится вручную. Выбор сохраняется между запусками. Такая схема нужна, потому что сервер обычно поднимается за туннелем со сменным адресом.

## 🏗 Архитектура

```
┌──────────────────┐                          ┌──────────────────┐
│  Клиент Windows  │                          │  Веб-клиент PWA  │
│   C# · WPF       │                          │   JavaScript     │
└────────┬─────────┘                          └─────────┬────────┘
         │                                              │
         │          HTTP  ─ запрос → ответ              │
         │          WebSocket ─ доставка сама           │
         └──────────────────┬───────────────────────────┘
                            ▼
                  ┌──────────────────┐
                  │      Сервер      │
                  │ ASP.NET Core     │
                  │ Minimal API      │
                  └────────┬─────────┘
                           ▼
                  ┌──────────────────┐
                  │    Хранилище     │
                  │  файлы, без СУБД │
                  └──────────────────┘
```

**Два канала связи.** HTTP — для того, что делается по требованию: вход, история переписки, загрузка файлов. WebSocket — для того, что должно приходить само: новое сообщение, отметка о прочтении, входящий звонок. Опрос сервера в цикле не используется.

**Единый протокол.** Оба клиента обращаются к серверу одинаково: одни и те же эндпоинты, один формат сообщений, один протокол голоса. Веб-версия — не отдельный продукт, а второй интерфейс к той же системе; третий клиент добавляется без изменений на сервере.

## 📁 Структура репозитория

| Путь | Что внутри |
|---|---|
| [`Tebegram-client/`](Tebegram-client) | десктопное приложение под Windows (C#, WPF, .NET 8) |
| [`Tebegram-server/`](Tebegram-server) | сервер (C#, ASP.NET Core, Minimal API) |
| [`docs/`](docs) | веб-клиент PWA; эта же папка раздаётся через GitHub Pages |
| [`Installer/`](Installer) | сборка установщика (Inno Setup) |
| [`Adress.txt`](Adress.txt) | **адрес сервера**: клиенты читают из него первую строку при выборе источника «main» |
| `Tebegram-client/Adress.txt` | зеркало предыдущего файла для уже установленных клиентов 2.0.0 — адрес в обоих должен совпадать |
| [`version.txt`](version.txt) | версия последнего релиза, по ней работает проверка обновлений |

## 🛠 Технологии

**Десктопный клиент** — C#, WPF, .NET 8. Привязка данных вместо ручной перерисовки, свои шаблоны элементов управления, NAudio для захвата и воспроизведения звука, собственная обработка сигнала (фильтрация, шумовой гейт, нормализация громкости).

**Сервер** — C#, ASP.NET Core в стиле Minimal API. Около 26 HTTP-эндпоинтов и два канала WebSocket: для сообщений и для голоса. Хранение — файлы с автосохранением по таймеру.

**Веб-клиент** — чистый JavaScript без фреймворков и без шага сборки. Service worker для офлайн-работы, Web Audio API и AudioWorklet для звонков, манифест PWA для установки на телефон.

**Протокол** — текстовый, со служебными разделителями. Общий для обоих клиентов, поэтому они полностью взаимозаменяемы.

## ⚠ Ограничения и планы

Проект учебный и рассчитан на доверенную локальную сеть. Слабые места известны и перечислены честно:

| Ограничение | Как правильно |
|---|---|
| Пароли хранятся открытым текстом | хэширование (bcrypt / Argon2) |
| Вход методом GET — пароль попадает в адрес и журналы | POST с телом запроса |
| WebSocket без аутентификации | токен сессии вместо идентификатора в адресе |
| Нет проверки прав на запросах | проверка владельца на стороне сервера |
| Хранение в файлах: нет транзакций и индексов | переход на SQLite |
| Голос передаётся без сжатия | кодек Opus |
| Групповых звонков нет — комната рассчитана на двоих | микширование на сервере |
